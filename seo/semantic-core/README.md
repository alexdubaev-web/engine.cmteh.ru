# Семантическое ядро каталога

Набор предназначен для SEO-редактора и специалиста по каталогу. Он связывает сохранённые поисковые наблюдения с текущими карточками и разделами, а спорные запросы оставляет на ручную проверку. Ядро охватывает все текущие позиции каталога и все формулировки в доступном снимке Вордстата; это не полный перечень всех запросов, которые существуют в поиске.

В текущем снимке от 12.10.2026 — 104 родительские проверки, 3795 строк таблиц и 3565 уникальных исходных строк. Генератор читает источники заново, поэтому актуальные количества и хеши входов приведены в `coverage.json`. SHA-256 входных текстовых файлов считается после нормализации CRLF к LF, поэтому хеши стабильны при разных правилах перевода строк в Windows/Linux checkout. `observations.csv` сохраняет каждую родительскую частотность и каждую исходную строку, включая строки интерфейса без числа. Для записей сохраняются исходная и нормализованная формулировки, значение либо пустое значение, период, регион, устройства, тип метрики, исходный запрос и индекс строки. Нормализация приводит регистр, пробелы и внешние кавычки Wordstat, но сохраняет внутреннюю пунктуацию, дефисы и начальные нули артикулов.

Показатель над таблицей является отдельным наблюдением `broad_total` или `quoted_total`. Строки под проверкой в кавычках помечены `legacy_row_broad_under_quoted_parent`: их число не трактуется как точная частотность фразы. Пересекающиеся измерения не суммируются и не заменяются максимумом. При нескольких измерениях у одного нормализованного запроса значение в `keywords.csv` оставлено пустым, а все evidence ID ведут к исходным числам в `observations.csv`. Пусто означает неизвестно; настоящий ноль остаётся нулём.

`keywords.csv` содержит наблюдавшиеся запросы, принятые для существующей страницы или редакционной задачи. У каждого есть один основной target; брендовая страница при необходимости дана дополнительной ссылкой. `measurement-queue.csv` объединяет явно непроверенные варианты из конкретных карточек и запросы, которым нужна ручная классификация. Это разные слои: кандидаты из каталожных названий не являются измеренными поисковыми формулировками, а очередь ручной проверки не считается активным ядром. `excluded.csv` объясняет неподходящие исходные строки; они не удалены из наблюдений.

В `core.json` каждый из 64 товаров и все 107 буквальных кодов представлены как текст. Дополнительный номер связан с карточкой каталога для поиска, но это не заявление о взаимозаменяемости. Короткие записи поставщика с косой чертой сохранены буквально и помечены для сверки; код не расширяется удалением разделителей. Измеренный alias допускается только для трёх явно проверенных в исходном исследовании записей. Для комбинаций бренд/категория используются только реально существующие сочетания и посадочные страницы; новые тонкие фильтры не создаются. Включены все текущие позиции John Deere, в том числе шесть, добавленных после исходного исследования; статья производителя или поисковая выдача не расширяет подтверждённую применимость.

Основной парсер отделяет последнее целое число от фразы и принимает разрядные группы вида `10 469`. Сомнительный длинный числовой хвост остаётся в очереди без изготовленной частотности. Проверки границ в генераторе покрывают SKU перед числом, разделённые тысячи, строку без числа и неоднозначный хвост. При автоматической маршрутизации конкретный тип детали важнее содержащегося в запросе слова: распылитель не превращается в форсунку, а клапан — в насос. Номер целого узла не подтверждает продажу его отдельного компонента. Неизвестные коды, несовпадающие типы, неподтверждённые модели техники и непонятные намерения направляются на ручную проверку.

`curated-decisions.json` содержит точечные решения по действительным строкам исторического исследования. `serp-research.json` — отдельное исследование границ и источников от 22.10.2026. Обе версии включены в `coverage.json` по SHA-256 и в сводку `core.json`. SERP-выборка не является полным топ-10, не доказывает позиции или совместимость и не несёт частотности Wordstat. Решения SERP и редактора не превращаются в новые поисковые замеры.

Для работы редактор сначала фильтрует `keywords.csv` по `primary_target`, `priority` и `period`, затем открывает все ссылки из `evidence_ids` в `observations.csv`. Уровни приоритета отражают только одно значение при ровно одном числовом свидетельстве; несколько значений не ранжируются через сложение или максимум. В `measurement-queue.csv` редактор сверяет коды и применимость с каталогом или документацией производителя, прежде чем принимать кандидат. Информационная потребность может быть отмечена темой к будущей статье, но не означает, что магазин оказывает ремонтные услуги. Для URL и типов страниц используйте `page-map.csv`.

Редакционные правила и границы публикации описаны в [`editorial/README.md`](../../editorial/README.md). Ядро само по себе ничего не публикует и не меняет карточки сайта.

Пересобрать датасет после изменения входов:

```powershell
python tools/build_semantic_core.py
```

Проверить инварианты и совпадение сохранённых результатов с детерминированным пересчётом:

```powershell
python tools/build_semantic_core.py --check
```

Проверка локальная, не обращается к сети, сверяет текущие хеши источников, сохранённые артефакты, полноту наблюдений, соответствие URL фактической карте сайта, уникальное владение кодами и покрытие всех SKU/кодов. Снимок Вордстата датирован 12.10.2026; новых частотностей не проверяли.
