# Техническое наполнение всех 58 карточек

Запрос: изучить каждый артикул ассортимента и добавить технические сведения.

Рабочая ветка: `codex/seo-wordstat-all-cards`; BASE `bf3bb8ac06797cbeeb8f5d277ef1ee38baeda7f9`.
Сохраняем незакоммиченные изменения предыдущего SEO-этапа. Публикация в этом запросе не выполняется.

## Исследование

- Проверить все 58 SKU по точному номеру, распределив поиск на Bosch, Delphi и остальные OEM.
- Основа новых технических утверждений: каталоги производителей и OEM, включая оригинальные документы производителя на сайтах дистрибьюторов.
- Допускаются собственные технические руководства профильных специалистов, например Merlin Diesel, с явным указанием автора. Их данные не называются подтверждением производителя; торговые агрегаторы и автоматически собранные карточки доказательствами не считаются.
- Для каждого факта записать русский текст, прямой URL, выдержку или краткое описание доказательства и дату проверки.
- Не переносить параметры семейства на конкретный артикул, не считать похожие номера заменами, не превращать частичный перечень техники в универсальную применимость.
- Отрицательные результаты, противоречия и неполные сведения сохранить в исследовательском журнале для каждого SKU.

## Интеграция после проверки источников

- Отдельный файл `data/product_technical.json`, ключи - существующие SKU.
- Карточки получают раздел технических данных с читаемыми парами «параметр - значение» и ссылками на использованные источники.
- Сведения без доказательства не публикуются. Для неполных данных допускается короткое полезное указание, что именно нужно проверить при подборе; отсутствие данных не маскируется общими характеристиками.
- Сохранить цены, склад, URL, изображения, существующую главную и пользовательские правки.
- Новые данные должны попадать в статический HTML без JavaScript. Все тексты и ссылки экранируются; ссылки источников должны иметь HTTPS URL.
- Не добавлять неподтверждённые параметры в Product schema.

## Приёмка

- Журнал охватывает ровно 58 существующих SKU, каждый опубликованный факт связан с источником.
- Проверить вручную спорные и наиболее подробные записи по оригиналам.
- Локальная проверка: `python tests/seo.test.py; if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }; python tests/catalog.test.py`.
- Узкая проверка покрытия, ссылок и соответствия исходных фактов сгенерированным карточкам; точечная проверка мобильной и десктопной карточки.
- Один независимый обзор существенных рисков, затем ограниченное исправление подтверждённых замечаний.
- В итогах отдельно указать число исследованных карточек, карточек с подтверждёнными новыми данными и нерешённые пробелы.

Стоп-условия для публикации отдельного факта: нет точной связи с SKU, источник не читается, конфликт не разрешён, сведения относятся к другому исполнению или общей серии.

## Уточнение пользователя после реализации

Ссылки на источники в карточках не нужны. Убрать публичные ссылки «Источник N» и список источников; сохранить характеристики, внутренние ссылки на доказательства в данных и исследовательских заметках. Адаптировать существующую проверку к этому представлению, сохранив сверку технических значений и внутренних источников.
