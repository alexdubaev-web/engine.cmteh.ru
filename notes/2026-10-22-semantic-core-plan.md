# Расширение семантического ядра

BASE: `0481ddd73192b2165189b265383fd97268ea886a`; ветка `codex/semantic-core`.

Цель — рабочее ядро для текущего ассортимента СМ ТЕХНО, с прослеживаемыми источниками и назначением запросов страницам. «Исчерпывающее» означает проверяемое покрытие всех текущих товаров, дополнительных номеров, типов деталей, представленных брендов и покупательских задач; это не утверждение о знании всех будущих поисковых формулировок.

1. Разобрать весь снимок Вордстата от 12 октября: 104 проверки и 3795 строк. Нормализовать запросы без потери начальных нулей/артикулов. Сохранить происхождение, период, регион, тип метрики и исходное значение каждой частотности; не складывать пересекающийся спрос и не заменять неизвестные значения нулями.
2. Покрыть все 64 SKU и 107 уникальных номеров текущего каталога, все реально представленные пары бренд/категория, пять опубликованных статей и коммерческие страницы. Дополнительный номер не считать гарантированным аналогом. Новые сочетания без наблюдения помечать как кандидаты для измерения.
3. Отделить покупку деталей, полезные вопросы и неподходящий спрос: ремонт как услуга, стенды, вакансии/обучение, форсунки омывателя/опрыскивателя, неподтверждённые марки техники. Не создавать автоматически страницы по городам, артикулам-заменам и сочетаниям брендов.
4. Сохранить живое исследование пограничных групп и новых John Deere. Честно указать поисковый источник: поисковая выборка не равна полному топ-10 Яндекса. Не выдавать ручную группировку за измеренную SERP-кластеризацию.
5. Подготовить JSON/CSV, таблицу страниц/приоритетов/недостающего контента и понятный отчёт; удобную Excel-книгу с артикулами как текстом. Привязать редакционные правила к одному источнику ядра без автоматической публикации статей и без изменения публичного сайта.
6. Проверить полноту покрытия, обработку источников, отсутствие выдуманных метрик, корректность целевых страниц, воспроизводимость файлов и фактический diff; одно независимое ревью. Команда проверки будет записана в README ядра. Продуктовые тесты нужны только при изменении продуктовых входов/сборки.
7. После проверок выполнить commit/push/PR/merge, проверить main, удалить свою временную ветку/worktree. Деплой не требуется для внутренних материалов исследования.

STOP: новые платные сервисы/затраты, CAPTCHA/необходимость нового доступа, неподтверждённые характеристики/совместимость, изменение приватных данных или публикации сайта. Недоступные новые частотности остаются неизвестными; старые измерения сохраняют исходную дату.
