# Применение ядра к сайту

BASE: `29829b7a1101d2f851d0ada0e5a156797b2459d2`; ветка `codex/semantic-implementation`.

Пользователь ожидал результат на работающем сайте, включая последующий переобход. Исследовательское ядро уже подготовлено; тексты старых карточек были улучшены ранее. Эта задача закрывает конкретные пробелы, не заменяет полезные тексты ради буквального повторения всех ключевых фраз.

## Решение

- Обновить пять существующих категорий и пять брендовых страниц по принятому ядру: корректные названия, уникальные метаданные, краткие пояснения по ассортименту и подбору, ссылки на реально представленные категории бренда и подходящие опубликованные статьи.
- Исправить слишком узкое название группы насосов: в ней есть не только ТНВД, но и электрические и подкачивающие насосы. Сохранить URL `/category/pumps/`, поиск, фильтры и товарные категории. Не называть RE543262 насосом высокого давления без подтверждения.
- Дополнить только те карточки, где есть конкретная покупательская неоднозначность из ядра: узел и отдельный компонент, комплектность, различия SCV/IMV/HPV, дополнительные номера. Не менять цены, остатки, номера, совместимость и изображения.
- Сохранить опубликованные статьи и их URL. Предложенные темы не становятся опубликованными автоматически; редакционные пилоты требуют отдельного принятия.
- После production-сборки сохранить правдивые изменения sitemap/очереди, пересчитать внутренние хеши ядра. Подготовить список фактически изменённых URL.

## Выполнение и проверки

Контент и минимальная интеграция сборки делегируются worker; lead проверяет фактический diff и production HTML. Единая локальная команда перед публикацией будет записана в отчёте: SEO-проверка, каталог, воспроизводимость ядра и `git diff --check` с остановкой при ошибке. Новые формальные тесты копии текста и GitHub Actions не добавлять. Одно независимое ревью, один ограниченный проход исправлений и узкая проверка закрытия.

Единая локальная команда выполнена lead с результатом PASS (88 страниц, 64 товара, 5 статей; пять проверок IndexNow; все 3899 наблюдений ядра):

```powershell
$env:PYTHONUTF8='1'; $env:PYTHONIOENCODING='utf-8'; $env:PUBLIC_SITE_URL='https://engine.cmteh.ru'; $env:INDEXABLE='true'; Remove-Item Env:INDEXNOW_KEY -ErrorAction SilentlyContinue; python build.py; if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }; python tools/build_semantic_core.py; if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }; python tests/seo.test.py; if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }; python tests/catalog.test.py; if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }; python tests/test_indexnow_queue.py; if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }; python tools/build_semantic_core.py --check; if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }; git diff --check; if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

Дополнительно проверены desktop 1440×1000 и mobile 390×844: страницы насосов и John Deere, переход между ними, загрузка видимых изображений, отсутствие горизонтального переполнения и ошибок JavaScript. Изолированный headless Playwright применён после ошибки прикрепления CUA; локальный API config подменён тестовым ответом, формы не отправлялись. Это проверка отображения, а не PHP/backend.

Публикация — только проверенным механизмом с новым manifest: сравнение текущего сервера с предыдущим релизом, закрытая резервная копия, атомарная замена, проверка всех новых хешей и HTTP. Backend, config, база, cron и загрузки не меняются. Перед apply проверить список изменений и возможность guarded rollback.

После подтверждённой публикации отправить фактически изменённые индексируемые URL Яндексу. Сначала проверить доступность Вебмастера; альтернативный существующий IndexNow использовать после проверки опубликованного ключа и списка URL. Приём уведомления не считать состоявшейся индексацией.

Проверка доступа: SSH к существующему хостингу работает, последняя публикация статьи подтверждена. Браузерный канал Вебмастера возвращает `Debugger detached while attaching`. IndexNow уже реализован, но публичный ключ не настроен. Для завершения уведомления разрешена минимальная настройка публичного ключа в данных сборки с сохранением приоритета переменной среды (включая явное пустое значение для отключения в тестовом fixture). Это не изменение паролей или прав доступа. Проверить совпадение ключевого файла по HTTPS, затем отправить только URL, подтверждённые новым release manifest и sitemap.

## STOP

Нет подтверждённого доступа/целевого окружения или безопасного отката; сервер изменился после предварительной проверки; новый платный сервис; неподтверждённые характеристики/применимость; изменение приватной конфигурации, БД, заказов или загрузок; новый редакционный пилот без принятия. При ограничении Вебмастера сохранить реальные статусы и использовать разрешённый безопасный путь уведомления.

После локальных проверок и ревью — commit/push/PR/merge по правилам владельца; проверить main и опубликовать согласованный пакет. Удалять только собственные временные ветку и worktree после успешной интеграции.
