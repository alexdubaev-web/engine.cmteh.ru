## Исходные факты

- Генератор Python отдаёт полные статические HTML-страницы; миграция не нужна.
- robots.txt, sitemap, абсолютные canonical, OG/Twitter, Organization, BreadcrumbList, категории, четыре статьи, delivery и contacts уже существуют.
- H1 главной содержит слоган вместо темы. В header отсутствуют delivery и contacts; footer не имеет прямой ссылки на общий каталог.
- На главной в исходном HTML присутствуют все 58 товаров, JavaScript показывает восемь и раскрывает остальные.
- `search` отсутствует в списке параметров с noindex в Worker и Apache; live HTTP это подтверждает.
- Мобильная навигация скрывается CSS и требует JS для открытия.
- Поля company в data/commerce.json пустые. Реальные контакты, реквизиты и условия оплаты/доставки запрошены у пользователя. Не выдумывать их.
- IndexNow уже реализован: содержательные изменения и удаления помещаются в очередь; CLI проверяет опубликованный ключ и отправляет очередь. Не уведомляет на обычных запросах.

## Задача A — компактная главная и коммерческие страницы

Файлы: build.py, seo.py (только необходимые изменения), public/assets/style.css, public/assets/app.js, data/commerce.json (только подтверждённые сведения/пустые расширения конфигурации), релевантные тесты.

- Тематический видимый H1 и заданные title/description главной, сохранить оформление hero и изображения.
- Все шесть пунктов header; на промежуточных ширинах использовать существующее мобильное меню без уменьшения читаемости. Обеспечить доступность ссылок без JS.
- В HTML главной ровно восемь прежних карточек и обычная ссылка на каталог. Поиск/фильтры главной ведут в полный каталог, чтобы усечение HTML не ограничивало поиск восемью товарами. Каталог/категории сохраняют существующую механику.
- Прямая ссылка на каталог в footer; существующие delivery/contacts ссылки сохранить.
- Доработать delivery: до выставления счёта подтвердить цену и наличие, сроки до оплаты, два CTA. Конкретные способы оплаты, НДС, договор, документы, перевозчиков и самовывоз показывать только из подтверждённой конфигурации.
- Contacts: H1 «Контакты», видимые данные из company, существующая форма. Компактный блок компании на главной через ту же конфигурацию. Пустые контакты не заменять фиктивными.
- Не изменять функцию card, товарные данные, CSS карточек/сетки, фото, цены, CTA, backend и бизнес-логику заявок.

Приёмка: точные метаданные, один H1, восемь неизменённых карточек, поиск полного каталога, HTML-ссылки, config/schema parity. Проверки: npm test; python tests/seo.test.py; python tests/catalog.test.py; production build. STOP: необходимость выдуманных фактов или изменения карточек.

## Итоговая проверка и отчёт

Ведущий проверяет реальный diff и запускает доступные проверки. Затем свежий reviewer проверяет весь diff и исправляет подтверждённые P0/P1/P2; после исправлений — второй свежий reviewer.

Проверить production через HTTP: главная, каталог, категория, статья, delivery, contacts, robots, sitemap, параметры, 404, редиректы. Playwright: 320/375/390/430/768/desktop, меню/клавиатура, формы без отправки данных, FAQ, поиск, отсутствие горизонтального overflow; HTML без JS. Сравнить разметку и размеры карточек с исходным состоянием.

Итоговый отчёт содержит исходные дефекты, список файлов/изменений, выполненные и сохранённые пункты ТЗ, результаты всех проверок и ограничения performance, ручные действия после деплоя и URL для Google/Яндекса. Реальная публикация и аккаунты поисковых систем не считаются выполненными без подтверждения.
