# Исправления независимого ревью — implementation plan

> **For agentic workers:** use the supplied bounded teamlead task brief and TDD; lead integrates isolated commits and runs fresh independent review.

**Goal:** исправить все десять подтверждённых ошибок ревью и конкретные дополнительные ошибки экспорта/переносимости; сохранить рабочую версию и закоммитить исправления.

**Architecture:** браузерные мутации корзины сериализуются транзакциями IndexedDB; сервер проверяет стабильное намерение повторной заявки по сохранённым данным. Python-пайплайн использует общий межпроцессный lock, staging и согласованную публикацию; отправка IndexNow подтверждает только отправленные ревизии.

**Tech Stack:** Node >=22, браузерный JavaScript/IndexedDB, Python stdlib для сборки, PHP/PDO/sodium. jsdom и fake-indexeddb допустимы только как dev-зависимости тестов.

**Spec:** `docs/reviews/2026-10-07/CODE-REVIEW.md`, запрос пользователя «Сделай комит и исправь все ошибки».

**BASE:** fb47257b8d04a398ead90ccda8047cbd54614043 — снимок существующих изменений и отчёта. Основная ветка исправлений: `fix/review-2026-10-07`.

**Ограничения**

- Не читать реальные конфиги/ключи, не отправлять настоящие заявки, SMTP или IndexNow, не деплоить.
- Сохранить внешний вид, цены, остатки, документы и выключенный приём заявок на демонстрации.
- Использовать RED→GREEN на настоящих сценариях; тесты не должны просто воспроизводить исходники или модель вместо изменённого компонента.
- Работы параллельны только в отдельных worktree. Один worker в основном checkout.
- Ведущий не пишет production-код; проверяет diff, интегрирует и запускает проверки.

**Review focus**

1. Пустая корзина после успешного заказа не должна мигрироваться заново из старого localStorage.
2. Уведомления разных вкладок не должны записывать устаревшие снимки и вызывать feedback loop.
3. Каталог может измениться или удалить товар до повтора; исходная заявка должна оставаться идемпотентной.
4. Исключение во второй записи или публикации не должно оставить потерянные предыдущие артефакты/смешанные остатки.
5. Тот же URL может измениться снова во время IndexNow; подтверждение старой ревизии не удаляет новую.
